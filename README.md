# tomcat-ant-demo-app

A single-servlet "Hello World" web application built for the
[`aviumlabs/tomcat-ant:9.0.123-alpine`](https://hub.docker.com/r/aviumlabs/tomcat-ant)
image. It compiles `src/main/java` with Apache Ant, packages a WAR, and deploys
it to a Tomcat instance via `deptools.py`.

- **Servlet API:** Java EE 8 (Servlet 4.0)
- **Build tool:** Apache Ant 1.10.18 (`build.xml`)
- **Servlet registration:** `@WebServlet(urlPatterns = {"/", "/hello"})`
  (annotation-based; `web.xml` has no `servlet-mapping`, only a welcome-file)
- **Runtime:** Apache Tomcat 9.0.123, OpenJDK 21
- **Container user:** `tomcat` (uid 965)

## Endpoints

The application context is `helloworld`. All URLs are served over HTTP on port
8090:

| URL | Result |
| --- | --- |
| `http://localhost:8090/helloworld/` | `Hello, World! from Hello World` (welcome-file redirect) |
| `http://localhost:8090/helloworld/hello` | `Hello, World! from Hello World` |
| `http://localhost:8090/helloworld/hello?name=Avium` | `Hello, Avium! from Hello World` |

> The `@WebServlet(urlPatterns = {"/", "/hello"})` annotation registers both the
> root context and `/hello`. `web.xml` intentionally has no `servlet-mapping`.

## Build directory layout (inside the container)

The build runs under `BACKUP_HOME` (default `/opt/backup`) and produces:

```
${BACKUP_HOME}/helloworld/
├── src/                       # copied source tree (Maven layout)
├── build/
│   ├── WEB-INF/
│   │   ├── web.xml            # copied from src/main/webapp/WEB-INF/web.xml
│   │   ├── classes/           # compiled .class files (MUST be here)
│   │   └── lib/
│   │       └── servlet-api.jar
│   └── helloworld.war         # the deployable WAR
```

### Why classes must be under `WEB-INF/classes/`

Tomcat's web application classloader only scans `WEB-INF/classes` and
`WEB-INF/lib`. If the build places compiled classes at the WAR **root**
(`classes/` instead of `WEB-INF/classes/`), Tomcat deploys them outside
`WEB-INF` and the `@WebServlet` annotation is never discovered — the servlet is
not registered and every request returns **404** (the webapp still deploys and
returns a 302 welcome-file redirect).

`build.xml` therefore compiles with:

```xml
<javac srcdir="src/main/java" destdir="${build.dir}/WEB-INF/classes" .../>
```

and packages the WAR from `basedir="${build.dir}"`, so the classes are nested
under `WEB-INF/classes/` inside the archive.

## Copy to container

Before building, the source must be present in the container at
`${BACKUP_HOME}/helloworld`. Because `docker cp` preserves the **host** uid,
it would place the files with the wrong ownership, so stage the source as a
tarball and extract it **as `tomcat`** inside the container.

On the **host**, package the source root (excluding `.git`):

```sh
tar -czf helloworld-src.tar.gz --exclude=.git -C tomcat-ant-demo-app .
```

Copy the tarball into the container with `docker cp`. This copies by path and
runs **no shell**, so it needs no `sh -c`. It does preserve the **host** uid,
so the tarball is only a staging artifact — it must be extracted **as `tomcat`**
so the files land with uid 965:

```sh
docker cp helloworld-src.tar.gz <container>:/opt/backup/helloworld-src.tar.gz
```

Extract it as `tomcat` so the files land directly in `${BACKUP_HOME}/helloworld`
(owned by uid 965). The container is Alpine Linux, whose default shell is `ash`
(`sh` is an alias for it), so use `sh -c`:

```sh
docker exec -u tomcat <container> sh -c "mkdir -p /opt/backup/helloworld && tar -xzf /opt/backup/helloworld-src.tar.gz -C /opt/backup/helloworld"
```

Remove the host-owned tarball so it does not linger with the wrong uid:

```sh
docker exec <container> rm /opt/backup/helloworld-src.tar.gz
```

After extraction, confirm ownership:

```sh
docker exec <container> ls -la /opt/backup/helloworld
```

Replace `<container>` with the container name or id. Then run `./build.sh` from
`${BACKUP_HOME}/helloworld` (see the Build section below).

## Prerequisites (inside the container)

Run all commands **inside the running container** as the `tomcat` user. The
container, by default, exposes:

| Port | Purpose |
| --- | --- |
| 8090 | HTTP (application) |
| 8443 | Tomcat Manager (TLS) |
| 8005 | Shutdown |

Required environment variables (set by the container):

| Variable | Value |
| --- | --- |
| `BACKUP_HOME` | `/opt/backup` |
| `WORKDIR` | `/opt/tomcat` |
| `SECRETS_HOME` | `/opt/secrets` |
| `CATALINA_HOME` | `/usr/local/tomcat` |
| `CATALINA_BASE` | `/opt/tomcat/instances/tc1` |
| `INSTANCE_NAME` | `tc1` |
| `TC_SECURE_PORT` | `8443` |

## Build

```sh
# Run inside the container as the tomcat user, from the source root:
docker exec <container> sh -c /opt/backup/helloworld/build.sh
```

`build.sh`:

1. Resolves `ANT_HOME`, `CATALINA_HOME`, and `BACKUP_HOME`.
2. If the source is not already at `${BACKUP_HOME}/helloworld`, copies it there.
3. Regenerates `build.properties` with the resolved `BACKUP_HOME` baked into
   `base.dir` (Ant cannot read environment variables from a static properties
   file).
4. Runs Ant, producing `${BACKUP_HOME}/helloworld/build/helloworld.war`.

> **Note:** Ant does not honor re-assigning an already-defined property.
> `build.sh` therefore bakes the resolved base directory (including the
> `/build` suffix) into `build.dir` in `build.properties`, and `build.xml`
> removes any redundant re-assignment.

## Deploy

```sh
docker exec <container> deptools.py --deploy-war /opt/backup/helloworld/build/helloworld.war
```

`deptools.py` (`/usr/local/bin/deptools.py`) uses the Tomcat Manager text
interface to deploy the WAR:

- Derives the application context from the WAR file name
  (`helloworld.war` → context `/helloworld`).
- Reads the RPA credentials from `/opt/tomcat/.tomcat.conf`
  (`rpauser = rpatomcat`, `rpapass = rpauser.pass` in `${SECRETS_HOME}`).
- Sends `PUT /manager/text/deploy?path=/{app}&update=true` with the WAR bytes.
- Logs to `${BACKUP_HOME}/deptools.log`.

## Ownership

All build artifacts and deployed files must be owned by `tomcat` (uid 965),
**not** host uid. `docker cp` preserves host uid ownership, so files
must be staged via `tar` extraction as `tomcat` inside the container.
`chown`/`chmod` cannot escalate past the current uid, so any non-tomcat uid leftover
must be renamed aside (not deleted) rather than force-chowned.

## Files

- `build.sh` — Build orchestrator.
- `build.xml` — Ant build (`init`, `compile`, `war`, `clean`).
- `build.properties` — Ant properties template (regenerated by `build.sh`).

- `src/main/java/com/aviumlabs/helloworld/HelloServlet.java` — The servlet.
